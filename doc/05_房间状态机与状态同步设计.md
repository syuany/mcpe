## 一、 连接生命周期有限状态机 (Connection State Machine)

客户端与服务端的连接生命周期由严密的底层状态机驱动：

```mermaid
stateDiagram-v2
    [*] --> Handshaking: TCP 建立 (SYN/ACK)
    
    state Handshaking {
        [*] --> WaitingHandshakePacket
        WaitingHandshakePacket --> ValidateVersion: 收到 Handshake (0x00)
    }

    ValidateVersion --> Status: NextState == 1 (列表探测模式)
    ValidateVersion --> Login: NextState == 2 && Version == 340 (登录模式)
    ValidateVersion --> Disconnected: Version != 340 (协议版本不符，直接踢出)

    state Status {
        [*] --> StatusReady
        StatusReady --> StatusReplied: 收到 Status Request (0x00) -> 下发 MOTD JSON
        StatusReplied --> PingPong: 收到 Ping (0x01) -> 下发 Pong (0x01)
    }
    Status --> Disconnected: 探测完成 / 客户端主动断开

    state Login {
        [*] --> WaitingLoginStart
        WaitingLoginStart --> Authenticating: 收到 Login Start (0x00)
        Authenticating --> LoginSuccess: 提取 Bungee IP 或生成离线 UUID
    }
    Login --> Play: 下发 Login Success (0x02)

    state Play {
        [*] --> Joining: 下发 Join Game (0x23)
        Joining --> SpawnLobby: 下发大厅 0x20 Chunks + 0x2F Pos & Look (TeleportID=T)
        SpawnLobby --> InLobby: 收到 Teleport Confirm (0x00, TeleportID=T)
        
        state InLobby {
            [*] --> Idle
            Idle --> Moving: 收到 0x0E/0x0F/0x10 移动包 (多播广播)
            Idle --> Chatting: 收到 0x02 聊天包 (房间多播 / 指令执行)
            Idle --> SwitchWorld: 踩中跑酷门 / 执行 /join
        }

        SwitchWorld --> InParkour: 下发 0x35 Respawn + 跑酷 Chunks + 传送起点
        
        state InParkour {
            [*] --> ParkourRunning: 跑酷计时开始
            ParkourRunning --> FallReset: 触发掉落重置 (Y < fall_y) -> 瞬移回起点
            ParkourRunning --> Finished: 触发终点判定盒 -> 记录耗时与广播
        }
        Finished --> InLobby: 延迟 3s 下发 0x35 切回大厅
    }

    Play --> Disconnected: 心跳超时 30s / 主动离线 / 跨服切出
    Disconnected --> [*]: 资源安全回收
```

## 二、 游戏房间状态机 (Room State Machine)

跑酷小游戏支持**单人竞速练习**与**多人同屏竞速**两种模式。每个房间运行独立的生命周期状态机：

```mermaid
stateDiagram-v2
    [*] --> WAITING: 房间初始化 / 地图就绪

    state WAITING {
        [*] --> WaitingPlayers: 等待玩家加入
        WaitingPlayers --> Ready: 玩家人数达到开赛阈值 / 队长点击开始
    }

    WAITING --> COUNTDOWN: 触发开始
    state COUNTDOWN {
        [*] --> Timer3s: 倒数 3 秒 (下发标题/音效 Title 0x48)
        Timer3s --> PrepareWorld: 向所有成员下发 0x35 Respawn + 跑酷 Chunks
    }

    COUNTDOWN --> PLAYING: 倒计时结束 (GO!)
    state PLAYING {
        [*] --> Running: 启动高精度单调时钟计时器
        Running --> CheckpointUpdate: 玩家踩中检查点
        Running --> ResetPosition: 玩家跌落 (Y < fall_reset_y)
        Running --> PlayerFinish: 玩家到达终点
    }

    PLAYING --> ENDED: 所有玩家完成 / 比赛超时 (如 300s)
    state ENDED {
        [*] --> AnnounceWinner: 全服通报获胜榜单
        AnnounceWinner --> ReturnLobby: 倒计时 5s 下发 0x35 切回大厅
    }

    ENDED --> WAITING: 重置房间数据与计时器
```

## 三、 0x35 无缝切世界时序 (World Transition Sequence)

客户端无需断开连接，即可在微秒级完成大厅与跑酷地图之间的平滑过渡：

```mermaid
sequenceDiagram
    autonumber
    actor Player as 客户端 Client
    participant Server as MCPE 房间调度引擎
    participant World as 目标游戏世界 (ParkourWorld)

    Player->>Server: 步入传送门 或 输入 /join spiral
    Server->>Server: 分配房间，从内存载入目标跑酷 Schematic
    Server->>Player: 1. 发送 0x35 Respawn 数据包 (Dimension=0, Difficulty=1, GameMode=2)
    Note over Player: 客户端黑屏刷新，清空原有大厅区块渲染缓存
    Server->>World: 查询起点周围视距区块列表
    loop 发送目标地图区块
        Server->>Player: 2. 发送 0x20 Chunk Data (批量下发跑酷跑道方块)
    end
    Server->>Player: 3. 发送 0x2F Player Position And Look (瞬移至跑道起点, 携带 Teleport ID)
    Player->>Server: 4. 回传 0x00 Teleport Confirm (闭环确认)
    Server->>Server: 5. 启动当前玩家高精度计时器 (steady_clock::now())
    Server->>Player: 6. 发送 Title (0x48) "3... 2... 1... GO!"
```

## 四、 跑酷游戏判定核心算法

### 4.1 掉落安全熔断 (Fall Reset)
跑酷地图均为浮空跑道。为避免玩家掉入虚空卡死或死亡掉落等待：
- 服务端在每次消费客户端 `Player Position (0x0E/0x10)` 时，提取 $Y$ 轴坐标；
- 若 $Y < \text{fall\_reset\_y}$（配置项，如 $Y < 35.0$）：
  - 服务端立即向客户端强制下发 `0x2F Player Position And Look`，坐标重置为起点（或最近激活的 Checkpoint）；
  - 客户端瞬间被拉回跑道，不扣血、不死亡、计时不中断，体验极佳。

### 4.2 终点包围盒检测 (AABB Collision)
终点设置一个三维空间包围盒（Axis-Aligned Bounding Box）：
$$\text{Box} = [X_{\min}, X_{\max}] \times [Y_{\min}, Y_{\max}] \times [Z_{\min}, Z_{\max}]$$
当玩家坐标 $(x, y, z)$ 满足：
$$X_{\min} \le x \le X_{\max} \land Y_{\min} \le y \le Y_{\max} \land Z_{\min} \le z \le Z_{\max}$$
判定为触碰终点：
1. 记录完成时间戳：$\Delta t = \text{now}() - t_{\text{start}}$（精确到毫秒）；
2. 格式化通报消息：“§a[跑酷] 恭喜玩家 §e%s §a通关！用时: §b%.2f 秒！”；
3. 将成绩插入本地排行榜（内存有序集合 `std::set` / SQLite / Redis）。

## 五、 20 TPS 物理主循环与节拍器模型 (Fixed Timestep Loop)

主世界采用基于单调时钟与时间累加器（Accumulator）的高精度补偿算法，维持恒定 20 TPS（每 Tick 50ms）：

```cpp
void WorldTicker::run() {
    using namespace std::chrono;
    constexpr nanoseconds kTickInterval(50'000'000); // 50ms
    constexpr nanoseconds kMaxAccumulator(250'000'000); // 防死亡螺旋阈值: 250ms (5 Ticks)

    auto last_time = steady_clock::now();
    nanoseconds accumulator(0);

    while (running_.load(std::memory_order_relaxed)) {
        auto current_time = steady_clock::now();
        accumulator += (current_time - last_time);
        last_time = current_time;

        if (accumulator > kMaxAccumulator) {
            accumulator = kMaxAccumulator;
        }

        while (accumulator >= kTickInterval) {
            tick(); // 消费 MPSC 队列任务，更新房间倒计时与位置校验
            accumulator -= kTickInterval;
        }

        auto elapsed = steady_clock::now() - current_time;
        if (elapsed < kTickInterval) {
            std::this_thread::sleep_for(kTickInterval - elapsed);
        }
    }
}
```
