## 一、 连接生命周期有限状态机 (Connection State Machine)

客户端与服务端的连接生命周期由严密的底层状态机驱动：

```mermaid
stateDiagram-v2
    [*] --> Handshaking: TCP 建立 (SYN/ACK)
    
    state Handshaking {
        [*] --> WaitingHandshakePacket
        WaitingHandshakePacket --> ValidateVersion: 收到 Handshake (0x00)
    }

    ValidateVersion --> Status: NextState == 1 (列表探测模式)
    ValidateVersion --> Login: NextState == 2 && Version == 340 (登录模式)
    ValidateVersion --> Disconnected: Version != 340 (协议版本不符，直接踢出)

    state Status {
        [*] --> StatusReady
        StatusReady --> StatusReplied: 收到 Status Request (0x00) -> 下发 MOTD JSON
        StatusReplied --> PingPong: 收到 Ping (0x01) -> 下发 Pong (0x01)
    }
    Status --> Disconnected: 探测完成 / 客户端主动断开

    state Login {
        [*] --> WaitingLoginStart
        WaitingLoginStart --> Authenticating: 收到 Login Start (0x00)
        Authenticating --> CapacityCheck: 提取 Bungee IP 或生成离线 UUID
        CapacityCheck --> Disconnected: 全服总人数已满 (下发 0x00 Disconnect)
        CapacityCheck --> LoginSuccess: 准入通过 (下发 0x02 Login Success)
    }
    Login --> Play: 跃迁至 Play 状态

    state Play {
        [*] --> Joining: 下发 Join Game (0x23)
        Joining --> SpawnLobby: 下发大厅 0x20 Chunks + 0x2F Pos & Look (TeleportID=T)
        SpawnLobby --> InLobby: 收到 Teleport Confirm (0x00, TeleportID=T)
        
        state InLobby {
            [*] --> Idle
            Idle --> Moving: 收到 0x0E/0x0F/0x10 移动包 (九宫格 AOI 多播广播)
            Idle --> Chatting: 收到 0x02 聊天包 (同分线多播 / 指令解析)
            Idle --> FallReset: 触发掉落重置 (Y < fall_reset_y) -> 瞬移回大厅出生点
            Idle --> SwitchShard: 输入 /lobby [id] 或满员调度
        }

        SwitchShard --> SpawnLobby: 下发 0x35 Respawn (-1 -> 0) + 新分线 Chunks + 0x2F 传送
    }

    Play --> Disconnected: 心跳超时 30s / 主动离线 / 跨服切出
    Disconnected --> [*]: 资源安全回收
```

## 二、 多实例大厅分线状态机 (Lobby Sharding State Machine)

引擎采用 Actor 模型实现大厅实例隔离。每个分线实例（`lobby-1`, `lobby-2`...）拥有独立的生命周期：

```mermaid
stateDiagram-v2
    [*] --> INIT: 实例创建 / 挂载全局只读 World 镜像

    state INIT {
        [*] --> AttachWorld: 绑定只读地图区块内存
        AttachWorld --> InitGrid: 初始化 SpatialGrid 与 EntityManager
    }

    INIT --> ACTIVE: 启动独立 20 TPS 线程与 MPSC EventQueue
    state ACTIVE {
        [*] --> Serving
        Serving --> PlayerJoined: 投递 PlayerJoinEvent (纳入九宫格 AOI)
        Serving --> PlayerMoved: 消费 PlayerMoveEvent (AOI 增量广播 / 虚空拉回)
        Serving --> PlayerLeft: 投递 PlayerLeaveEvent (广播 DestroyEntities 0x32)
        Serving --> BroadcastChat: 消费 ChatEvent (同分线零拷贝多播)
    }

    ACTIVE --> SHUTDOWN: 实例缩容 / 服务停止
    SHUTDOWN --> [*]: 停止 WorldTicker 线程并释放事件队列
```

> [!NOTE]
> 早期规划的跑酷小游戏因强依赖原版复杂的红石电路、压力板与活塞等原版生存物理，违背轻量大厅微服务架构原则，已解耦并归档至 `archive/parkour/`。

## 三、 0x35 无缝跨分线切换时序 (Cross-Instance Transition Sequence)

客户端无需断开 TCP 连接，即可在微秒级完成不同大厅分线之间的平滑过渡：

```mermaid
sequenceDiagram
    autonumber
    actor Player as 客户端 Client
    participant Server as MCPE 协议层 (ClientSession)
    participant LM as 分线调度中心 (LobbyManager)
    participant L1 as 原大厅分线 (lobby-1)
    participant L2 as 目标大厅分线 (lobby-2)

    Player->>Server: 输入 /lobby 2 (或大厅满员触发调度)
    Server->>LM: transferPlayer(session, "lobby-2")
    LM->>L1: 投递 PlayerLeaveEvent
    Note over L1: 从 lobby-1 九宫格移除，向邻居广播 0x32 DestroyEntities
    Server->>Player: 1. 发送 0x35 Respawn (Dimension=-1 -> 0, 清空客户端旧渲染缓存)
    loop 流式下发大厅区块
        Server->>Player: 2. 发送 0x20 Chunk Data (补齐目标分线区块)
    end
    Server->>Player: 3. 发送 0x2F Player Position And Look (瞬移至大厅出生点, TeleportID=T)
    Player->>Server: 4. 回传 0x00 Teleport Confirm (闭环确认)
    LM->>L2: 投递 PlayerJoinEvent
    Note over L2: 纳入 lobby-2 九宫格 AOI，双向同步周围可见实体
```

## 四、 大厅空间安全与位置判定核心算法 (Lobby Spatial Safety)

### 4.1 掉落安全熔断 (Fall Reset)
大厅地图通常包含边界或浮空岛屿。为避免玩家意外跌落虚空死亡卡死：
- 服务端在每次消费客户端 `Player Position (0x0E/0x10)` 时，提取 $Y$ 轴坐标；
- 若 $Y < \text{fall\_reset\_y}$（来自 `assets/maps/<map>.ini`，默认 $Y < 30.0$）：
  - 实例主线程立即向客户端下发 `0x2F Player Position And Look`，坐标重置为大厅出生点；
  - 同时当场修改内部 `PlayerMoveEvent` 坐标，确保 `SpatialGrid` 九宫格归属立即被同步矫正；
  - 客户端瞬间被拉回出生点，不扣血、不死亡，保持丝滑体验。

### 4.2 跨服传送门包围盒检测 (Portal AABB Detection)
大厅支持配置传送门三维空间包围盒（Axis-Aligned Bounding Box）：
$$\text{Box} = [X_{\min}, X_{\max}] \times [Y_{\min}, Y_{\max}] \times [Z_{\min}, Z_{\max}]$$
当玩家坐标 $(x, y, z)$ 满足：
$$X_{\min} \le x \le X_{\max} \land Y_{\min} \le y \le Y_{\max} \land Z_{\min} \le z \le Z_{\max}$$
判定为步入传送门：
1. 检查传送门防抖冷却时间戳（如 5 秒冷却），防止高频触发；
2. 构造并发送 `0x18 Plugin Message`（通道 `"BungeeCord"`，内容 `"Connect"` + 目标子服名）；
3. 外部 BungeeCord / Velocity 网关自动完成跨服路由。

## 五、 20 TPS 物理主循环与节拍器模型 (Fixed Timestep Loop)

主世界采用基于单调时钟与时间累加器（Accumulator）的高精度补偿算法，维持恒定 20 TPS（每 Tick 50ms）：

```cpp
void WorldTicker::run() {
    using namespace std::chrono;
    constexpr nanoseconds kTickInterval(50'000'000); // 50ms
    constexpr nanoseconds kMaxAccumulator(250'000'000); // 防死亡螺旋阈值: 250ms (5 Ticks)

    auto last_time = steady_clock::now();
    nanoseconds accumulator(0);

    while (running_.load(std::memory_order_relaxed)) {
        auto current_time = steady_clock::now();
        accumulator += (current_time - last_time);
        last_time = current_time;

        if (accumulator > kMaxAccumulator) {
            accumulator = kMaxAccumulator;
        }

        while (accumulator >= kTickInterval) {
            tick(); // 消费 MPSC 队列任务，更新房间倒计时与位置校验
            accumulator -= kTickInterval;
        }

        auto elapsed = steady_clock::now() - current_time;
        if (elapsed < kTickInterval) {
            std::this_thread::sleep_for(kTickInterval - elapsed);
        }
    }
}
```
